Token Optimizer · benchmarks and results

Fewer tokens. Same answers.

Token Optimizer trims what your AI coding assistant sends to the model, and leaves in everything it needs to know. This page shows what that saves, in two separate measurements: a controlled benchmark anyone can rerun, and one person's real month of coding.

What it does

Six ways your context gets lighter

Most of what a coding assistant pays for is not your question. It is the tool output, file contents and earlier turns that get resent on every call. Token Optimizer works on that overhead with six levers. All of them run automatically.

Tool-output compression
Long command output is archived to disk and replaced with a short stub. The full text is one call away if the assistant needs it.
Cross-turn dedup
Content that would be resent unchanged on the next turn is sent once.
Delta-read
Re-reading a file you just edited returns only what changed, not the whole file again.
Structure-map skeletons
A very large first read of a code file arrives as its signatures and imports, with the full file archived and recoverable.
Checkpoint-restore
When a long session compacts, the decisions and files in play are restored instead of re-read.
Model routing
Routine turns can run on a lighter model, so the expensive one is used where it matters.

Why this is a floor, not a forecast

Terminal-Bench tasks are short, single-shot terminal jobs. The agent rarely re-reads a file, never runs long enough to compact, and the model is held fixed. That leaves exactly one of the six levers with anything to do. The other five carry real multi-file coding work and never get a turn here.

What a full setup saved in 30 days of real coding

This is a different kind of number. It is not the benchmark. It is the author's own dashboard over 30 days of everyday work, with all six levers running. It shows the shape of the saving when everything fires. It does not predict yours.

66.7M

The month cost 152.3M tokens. Doing the same work without Token Optimizer would have cost about 219M. The gap splits into two parts, and they are labelled differently because they are known differently.

152.3M spent 32.8M saved, metered 33.9M saved, estimated

Metered means each saving was logged as it happened: a result archived, a repeat read skipped, a lighter model used. Estimated means the saving is modelled from what happened, such as content that would have been re-read on later turns had it stayed in context. Safety

What it never breaks

Saving tokens is only worth something if the assistant still knows what it needs to know, your prompt cache still works, and nothing sensitive gets mangled. Three checks cover that.

Your prompt cache stays warm

Compression that rewrites content already in the cached prefix forces the model to re-bill that prefix. Token Optimizer archives to a stable stub instead, so the cached prefix stays intact. In long sessions the cache-hit rate is slightly higher with archives on than off.

The full output is always one step away

Nothing is thrown away. Every compressed result is archived first and can be expanded on demand, so a stub is never the only copy.

87 safety fixtures, all passing

Each fixture is a real piece of output with a list of things that must survive compression and a list of things that must never appear. The rules that matter most: credentials such as AWS keys, personal access tokens and Slack tokens are never stripped, and error output and the output of failed commands always pass through untouched. Rerun it yourself with python3 scripts/benchmark.py.

Why trust these numbers

How to read them, in four lines

  • Two measurements, never combined. The benchmark is a controlled floor with one lever active. The real month is one person's usage with all six. Neither is used to inflate the other.
  • Intervals before point estimates. The whole 81-task suite was run and its point estimates are shown. A saving is claimed only where the 95% interval stays below zero, which is the 57-task cohort. Anything wider is called directional and left at that.
  • Metered and estimated are labelled every time. Where a figure is modelled rather than logged, the label says so, on this page and on the dashboard.
  • The parts that touch your data run on your own history. The savings report comes from python3 scripts/measure.py savings and the 87-fixture safety suite from python3 scripts/benchmark.py, both shipped in the repo. The Terminal-Bench comparison runs on the public Harbor + Terminal-Bench 2 harness, with the full method documented here.
